# Risk register

| Risk                                                                  | Impact                                                                                                                         | Mitigation                                                                                                                                                                           | State                  |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------- |
| GitHub CLI unavailable in the base environment                        | Public repository and Release operations require a project-local authenticated client or an existing signed-in browser session | Install any required release client only inside this project, authenticate without committing credentials, and publish only after every local release gate passes                    | Open until publication |
| Direct GitHub access unreliable                                       | Fetches and release operations may fail                                                                                        | Preserve canonical remote; register a read-through mirror and local Git bundle                                                                                                       | Mitigated locally      |
| Node not on PATH                                                      | Build/test blocked                                                                                                             | Use pinned portable Node 24.19.0 under `third_party/toolchains` through `scripts/env.ps1`                                                                                            | Mitigated locally      |
| Inherited dependency or asset license ambiguity                       | Release compliance issue                                                                                                       | File-level audit completed; generate the final lockfile license inventory after the dependency graph stabilizes                                                                      | Mitigated for Round 0  |
| Real WeChat API has irreversible side effects                         | Unintended account mutation                                                                                                    | Approved-only gate, explicit confirmation, environment-only secrets, default mock mode                                                                                               | Designed               |
| Desktop packaging downloads binaries                                  | Non-reproducible or off-project cache                                                                                          | Electron 28.3.3 is pinned, hashed, registered, and cached in `.cache/electron`                                                                                                       | Mitigated locally      |
| Browser storage lifecycle races                                       | Saved articles appear missing after reload                                                                                     | StorageManager shares in-flight initialization; Playwright verifies IndexedDB paths, last-file recovery, and UI reload                                                               | Mitigated in Round 1   |
| External file edits race with autosave                                | Newer disk content could be overwritten                                                                                        | Expected-content/hash checks reject conflicts; editor buffers remain in memory; previous article backup is kept                                                                      | Mitigated in Round 1   |
| Cross-file state transition interruption                              | Article and event history could momentarily differ                                                                             | Every event chain is validated before the next transition; backups and recovery data stay local; a future transactional journal can close the final crash window                     | Open, bounded          |
| Inherited unpinned `doocs/md` helper provenance                       | Release attribution ambiguity                                                                                                  | Round 1 removed the inherited hand-written helper and uses the already-registered CryptoJS UTF-8/Base64 implementation                                                               | Resolved in Round 1    |
| WeChat platform constraints change                                    | Lint rules become stale or overly strict                                                                                       | Keep limits in versioned configuration, record the official URL and verification date, and treat contradictory documentation conservatively                                          | Monitored in Round 2   |
| Remote images target internal services                                | SSRF or metadata exposure                                                                                                      | Explicit import only; protocol, DNS/IP, redirect, timeout, byte, MIME, and metadata-address checks fail closed                                                                       | Mitigated in Round 2   |
| Malicious or oversized media                                          | Script execution, privacy leak, or resource exhaustion                                                                         | Byte-level MIME inspection, SVG active-content rejection, pixel/file budgets, immutable originals, and privacy-cleaned derived outputs                                               | Mitigated in Round 2   |
| Approval reused after content change                                  | Stale review authorizes different bytes                                                                                        | Bind every evidence hash; append an invalidation record before approved-source writes; automatically return Web/CLI state to draft or reviewed                                       | Mitigated in Round 2   |
| Browser-only review cannot produce Chromium evidence                  | A browser build could otherwise be mistaken for platform preview proof                                                         | Browser builds never synthesize `preview-report.json`; Electron/CLI loads real local Chromium screenshots and hashes, and missing or stale evidence keeps approval locked            | Mitigated in Round 3   |
| Draft response is lost after remote creation                          | An automatic retry could create a duplicate draft                                                                              | Enter `UNKNOWN_REMOTE_STATE`, block retries by idempotency key, persist evidence, and allow only read-only three-result reconciliation                                               | Mitigated in Round 3   |
| Media upload succeeds before draft creation                           | Remote account retains orphaned media                                                                                          | Persist each upload immediately, report `FAILED_WITH_REMOTE_ASSETS`, never claim rollback, and require explicit human review before another real attempt                             | Mitigated in Round 3   |
| Agent or CI reaches real account side effects                         | Unattended account mutation                                                                                                    | Host-process signal checks, TTY/Web attestation, no MCP real execute tool, one-time bound challenge, and mock-only CI environment                                                    | Mitigated in Round 3   |
| Official API contract or account permission differs                   | Live draft attempt fails or uses wrong cover semantics                                                                         | Version the verified official contract, require account doctor/capability checks, and keep live status unverified until a user-approved real receipt exists                          | Open, bounded          |
| Inherited `apps/server` license metadata differs from pinned upstream | Redistributing the component could exceed proven rights                                                                        | Scheme A removes the component from the workspace, lockfile, build, Docker context, clean public history, SBOM and release artifacts; automated boundary tests reject reintroduction | Resolved by exclusion  |
| Generic formatter rewrites approved or hash-bound evidence            | Valid approval and preview hashes become stale or misleading                                                                   | Exclude `content/**`, `operations/**`, `artifacts/**`, and generated JSON reports from formatting hooks; regression-test the exclusions                                              | Resolved in Round 5    |
| Electron builder infers publication from CI or token context          | A candidate could be uploaded before explicit release authorization                                                            | Every candidate build passes `--publish never`; publication is isolated in a second job gated by the owner-controlled `MPFORGE_PUBLIC_RELEASE_AUTHORIZED` variable                   | Mitigated in Round 5   |
| Windows candidate is unsigned                                         | Users cannot verify a publisher identity through Authenticode                                                                  | Label the artifact unsigned, publish its SHA-256, and require an owner-supplied signing identity before making any signed-installer claim                                            | Open, explicit         |
